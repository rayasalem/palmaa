# التحقق من أن كل شيء تمام في المشروع

استخدم هذه القائمة للتأكد أن المشروع جاهز للتشغيل المحلي أو النشر.

---

## 1) البيئة والإعدادات

| الخطوة | ماذا تفعل | كيف تتأكد |
|--------|-----------|-----------|
| ملف البيئة (Frontend) | انسخ `.env.example` إلى `.env` في **جذر المشروع** واملأ القيم. | وجود ملف `.env` وأن `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` و `VITE_API_URL` معبأة. |
| ملف البيئة (Backend) | انسخ `server/.env.example` إلى `server/.env` واملأ القيم. | وجود `server/.env` وأن `SUPABASE_URL` و `SUPABASE_SERVICE_KEY` و `JWT_SECRET` معبأة. |
| الاتصال بـ Supabase | تأكد أن الـ URL والـ keys تطابق مشروعك في Supabase Dashboard. | تسجيل الدخول من الموقع أو من API يعمل بدون 401. |

---

## 2) التبعيات والبناء

| الخطوة | الأمر | النتيجة المتوقعة |
|--------|-------|-------------------|
| تبعيات الواجهة | `npm install` (من جذر المشروع) | تنتهي بدون أخطاء. |
| تبعيات الباكند | `cd server` ثم `npm install` | تنتهي بدون أخطاء. |
| بناء الواجهة | `npm run build` (من الجذر) | ينجح وينشئ مجلد `dist/`. |
| (اختياري) تنسيق الكود | `npm run format:check` | لا توجد ملفات تحتاج تنسيق (أو شغّل `npm run format`). |
| (اختياري) Lint الباكند | `npm run lint` | لا أخطاء أو معالجة التحذيرات. |

---

## 3) قاعدة البيانات (Supabase)

| الخطوة | ماذا تفعل | كيف تتأكد |
|--------|-----------|-----------|
| الـ Migrations | شغّل الـ migrations على قاعدة المشروع (مثلاً من Supabase SQL Editor أو `npx supabase db push` إن متصل بمشروع Supabase). | لا تظهر أخطاء عند التشغيل. |
| ملف setup.sql | إن أردت تطبيق كل التعديلات دفعة واحدة، نفّذ `supabase/setup.sql` من SQL Editor (بعد وجود الجداول الأساسية). | تنفيذ السكربت ينجح. |
| الجداول الأساسية | تأكد وجود جداول مثل: `users`, `products`, `orders`, `order_items`, `carts`, `cart_items`, `merchant_offers`, `shop_offers`. | تظهر في Supabase → Table Editor. |

---

## 4) التشغيل المحلي

| الخطوة | الأمر | النتيجة المتوقعة |
|--------|-------|-------------------|
| تشغيل الباكند | من مجلد `server`: `npm run dev` | السيرفر يعمل على المنفذ 5000 (أو المنفذ في `PORT`). |
| تشغيل الواجهة | من جذر المشروع: `npm run dev` | Vite يفتح على المنفذ 3000 (أو المنفذ المعروض). |
| رابط الواجهة | افتح المتصفح على الرابط الذي يظهر (مثلاً `http://localhost:3000`). | الصفحة الرئيسية تظهر. |
| رابط الباكند | تأكد أن `VITE_API_URL` في `.env` يشير إلى الباكند المحلي (مثلاً `http://localhost:5000`). | طلبات الموقع تذهب للسيرفر المحلي وليس لـ Render. |

---

## 5) التحقق من الوظائف الأساسية

| الوظيفة | كيف تتحقق |
|---------|-----------|
| الصفحة الرئيسية | تفتح بدون أخطاء في الكونسول. |
| الكتالوج / المنتجات | تظهر منتجات (أو رسالة مناسبة إن لم يوجد بيانات). |
| تسجيل الدخول | تسجيل الدخول يعمل ويرجع للموقع بدون 401. |
| لوحة التاجر | بعد تسجيل الدخول كتاجر، لوحة التاجر والعروض تفتح. |
| السلة | إضافة منتج للسلة وعرض السلة يعملان. |
| الطلبات | إنشاء طلب (أو صفحة الطلبات) يعمل بدون أخطاء. |

---

## 6) قبل النشر (Production)

| الخطوة | ماذا تفعل |
|--------|-----------|
| متغيرات الإنتاج | على (Render / Vercel / إلخ) ضبط كل متغيرات البيئة من `.env.example` بقيم الإنتاج. |
| رابط الواجهة | `FRONTEND_URL` في الباكند يطابق رابط الموقع الفعلي (مثلاً `https://palma.ps`). |
| رابط الباكند | `VITE_API_URL` (أو المكافئ في البناء) يشير لرابط الباكند الحقيقي (مثلاً `https://palmaa.onrender.com`). |
| JWT و Supabase | `JWT_SECRET` قوي ومختلف عن التطوير؛ مفاتيح Supabase خاصة بمشروع الإنتاج. |
| النسخ الاحتياطي | أخذ نسخة من الداتابيس دورياً (مثلاً عبر `pg_dump` أو تصدير من Supabase). |

---

## تشغيل التحقق التلقائي (بناء + وجود ملفات البيئة)

من جذر المشروع:

```bash
npm run verify
```

إذا انتهى الأمر بنجاح (exit 0) فالبناء وملفات البيئة الأساسية موجودة. باقي الخطوات (الداتابيس، التشغيل، والوظائف) تحقق منها يدوياً حسب الجدول أعلاه.
